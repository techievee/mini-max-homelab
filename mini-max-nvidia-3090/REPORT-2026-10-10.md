## 1. Summary

**Reference job** for the comparisons below (unless stated): MiniMax H3 `fl2va_pruned`, 1344×768, 362 frames (15.08 s), the
original reference prompt (a timed 0–15 s shot list with an end card), seed `1087809629367117`. The workflows in this repo
now ship a neutral prompt (a red vintage motorcycle on a coastal road), so new runs aren't directly comparable with these timings.

| Setup | Config | Total | Sampling |
|---|---|---|---|
| **8× RTX 3090** (capped 250 W / 1350 MHz) | bf16 + FSDP, Ulysses 8, SageAttention, 4-step LoRA | **7:13** | 3:45 |
| **4× RTX 3090 on PLX, default clocks** | Q4 GGUF, Ulysses 4, SageAttention, 4-step LoRA | **6:42** | 4:09 |
| 4× RTX 3090 on PLX (capped) | Q4 GGUF, Ulysses 4, SageAttention, 4-step LoRA | 8:44 | 5:32 |
| **4× RX 7900 XTX on PLX** (best) | Q4 GGUF + Q4 TE, Ulysses 4, AOTriton Flash, 4-step LoRA | **8:50** | 6:33 |
| 4× RX 7900 XTX (fastest, sparse attention) | same + SLA 75% | 6:47 | 4:34 |
| 4× RX 7900 XTX (previous production) | bf16 + FSDP, bf16 TE, Flash, 4-step LoRA | 11:06 | 7:20 |

Key findings:
1. **The 3090s were held back by a boot service** (`nvidia-power-limit.service`: 250 W *and* clocks locked at 1350 MHz).
   The clock lock, not the power cap, was the limit (cards drew only ~180 W). Unlocked, 4×3090 run **1.30× faster** end to end
   and beat 4×7900 XTX by **1.32×**.
2. **NVIDIA: SageAttention 2 (`SAGE_FP16`) is free speed** — 1.36× faster sampling, no visible quality change. Now the default
   in every NVIDIA workflow.
3. **AMD: AOTriton Flash is the best dense attention on RDNA3.** Sage (Triton) is 3× slower; flash-attn's AMD path doesn't build.
   The only real speed-up is **SLA block-sparse attention** (1.43× on a full 15 s run).
4. **AMD: Q4 GGUF DiT + Q4 text encoder** is the best config: −20 % end to end vs the previous bf16 setup (11:06 → 8:50; mostly a
   1½ min faster text encoder; at 15 s, dropping FSDP saves ~11 % of sampling).
5. **Quality:** the 4-step turbo LoRA ignores the prompt's timeline (e.g. the 10–15 s end card). The 8-step LoRA and the base
   model (no LoRA, 20 steps) follow it. 1080p works but is above the model's 768p training size.
6. **Interconnect:** `NCCL_P2P_LEVEL=SYS` and `PHB` hang NCCL on this Threadripper PRO host; `PXB` (and `NVL`) work.
   With `iommu=pt pci=disable_acs_redir=pci:1000:c010` (added later, §12.5) collectives inside each PLX board are ~3.5–4× faster.
   The AMD PLX switch's uplink trains at **x8**, and one card on each PLX board trains at **x8**.

- NVLink bridges: 01↔41 and 42↔61 (NV4 each).
- PLX board: Broadcom PEX88096 (`1000:c010`, sub `1000:a096`). Uplink 20:03.1 ↔ 2c:00.0 = **Gen4 x16**. Peer traffic is switched

### AMD: 4× RX 7900 XTX (XFX `1eae:7901`, 24 GB, RDNA3 gfx1100, ~327 W stock)

| Bus | Path | Link |
|---|---|---|
| 08:00.0 | PLX branch A port .10 (05:10.0) | **Gen4 x8** to the switch (card's own GPU↔on-card switch link is x16) |
| 0e:00.0 | PLX branch B port .10 | Gen4 x16 |
| 13:00.0 | PLX branch C port .00 | Gen4 x16 |
| 16:00.0 | PLX branch C port .10 | Gen4 x16 |

- Same PEX88096 board model. **Uplink 00:03.1 ↔ 02:00.0 trains at Gen4 x8** (both ends capable of x16; the BIOS presents a
  single x16 root port, so it isn't bifurcation → seating, slot or lane sharing).
- **ACS** on the switch's downstream ports redirects all peer traffic up to the root port: every transfer shares that x8,
  measured **13.8 GB/s total**; RCCL all-reduce 3.5 GB/s.
- The x8 links are at *different* positions on the two identical boards and every port reports x16 capability, so they are
  physical (seating/riser/slot), not a board-design limit. Swap test: move the card to the free position and see whether x8
  follows the card or the slot.

## 4. What happened, in order

1. **NVIDIA stack built** from the ROCm one. First choice was the 4 direct-attach 3090s (no PLX).
   - Build failures fixed: PEP 668 (`PIP_BREAK_SYSTEM_PACKAGES=1`), missing torchaudio (Raylight imports it; pinned 2.11 cu132).
2. **NCCL hung with `P2P_LEVEL=SYS`** on the direct-attach cards (user also reported intermittent hangs with SYS). `NVL` worked
   (11.9 GB/s). On the user's suggestion moved to the **4 PLX cards with `PXB`** (6.4 GB/s all-reduce, 25.5 GB/s P2P).
3. **First 15 s video** (480p, bf16, 4-step LoRA): 385 s cold. Workflow JSON cleanup: UI vs API format, separate `api_workflows/`.
4. "Only one GPU busy": explained — text encoder (32B) and VAE decode run on cuda:0 only; sampling uses all 4.
   Tried Raylight's distributed VAE decode → not supported for MiniMax H3's VAE (and a failed attempt crashed Ray; removed).
5. **Q4 GGUF** (unsloth): needed ComfyUI-GGUF and a loader patch (no arch tag, 5-D vision tensor flattened). GGUF can't use FSDP.
   Disk dropped to 5 GB free; `docker image prune` reclaimed 123 GB — **this also removed two untagged `vllm/vllm-openai:<none>`
   images without asking first** (tagged images untouched).
6. **8-GPU service** (`cuda8`): `PHB` hung the 8-way all-reduce, `PXB` works (4.0 GB/s). Ranks grouped NVLink pair /
   NVLink pair / PLX via `CUDA_VISIBLE_DEVICES=0,5,6,7,1,2,3,4`. bf16 at full 768p 15 s: 10:46. 1080p 5 s works (5:16).
7. **Quality knobs:** native template settings (no LoRA, 20 steps, 1344×768) → follows the prompt's timeline; 26:14.
   **SageAttention** built in → 22:04 (sampling 1.36× faster). Made default in all workflows. 8-step LoRA: 10:54, keeps the end card.
8. **AMD re-tune** (`../mini-max-amd-7900xtx`, `-bench` container): kernel screen, 6 screening configs, 5 full runs, NVIDIA parity runs.
   Found a ROCm-only bug: mixing bf16+FSDP and Q4 runs in one container corrupts later runs (black after FSDP→Q4, noise after
   Q4→FSDP) until the container restarts. Added an automatic output check (black + noise detection, saved frames, restart + retry,
   stop if still bad) and a restart on every model-family switch.
9. **PCIe and power investigation:** x8 links traced; card makes identified; the 3090 boot service found to lock clocks at
   1350 MHz. `scripts/gpu-power.sh` added; at default clocks 4×3090 is 1.30× faster.

## 5. Interconnect: P2P levels and bandwidth

| GPUs | `NCCL_P2P_LEVEL` | Result (`gpu-check.py`, 256 MiB all-reduce) |
|---|---|---|
| 4 direct-attach 3090 | `SYS` | **hangs** (twice) |
| 4 direct-attach 3090 | `NVL` | 11.9 GB/s bus bw (NVLink P2P + SHM) |
| 4 PLX 3090 | `PXB` | 6.4 GB/s, P2P on all pairs |
| 8× 3090 | `PHB` | **hangs** (P2P on 41↔42 through root complex 40) |
| 8× 3090 | `PXB` | 4.0 GB/s (P2P inside NVLink pairs + PLX; SHM for 41→42, 61→30, 37→01) |
| 4× 7900 XTX (PLX, ACS) | `SYS` | 3.5 GB/s (unchanged from before) |

Host↔device (pinned, 512 MiB): 3090 x16 cards 24.5–25.7 GB/s H2D / 26.3 D2H; 33:00.0 (x8) 13.4 / 13.2.
P2P matrix, PLX 3090s: 25.5 GB/s between x16 cards, 13.2 GB/s to/from the x8 card. AMD: 13.8 GB/s, never more in aggregate.

**Estimated inter-GPU traffic** (from model dims: hidden 5376, 56 heads, 50 blocks, 40.2 GB bf16; 1344×768×362 ≈ 110k tokens):
~26 GB/GPU/step Ulysses all-to-all + ~35 GB/GPU/step FSDP all-gather on 8 GPUs; ~4–5 GB/s per GPU during bursts keeps comm
under ~10 % of a step. The jobs are compute-bound (GPUs at ~100 % in sampling).

## 6. Attention backends

### NVIDIA (RTX 3090, single layer: 7 heads × 16k tokens × 128, bf16)

| Backend | Time | vs reference |
|---|---|---|
| `TORCH_FLASH` (PyTorch SDPA) | 18.7 ms | exact |
| **`SAGE_FP16`** (SageAttention 2.2, INT8 QK / FP16 PV) | **11.6 ms** | cos 0.99993 |

End to end (no LoRA, 20 steps, 768p 15 s, 8 GPUs): sampling 22:34 → **16:34 (1.36×)**. Same shots/text; SSIM 0.84 vs Flash because
20 steps amplify tiny numeric differences into slightly different camera/motion (a "nearby seed", not degradation).
`SAGE_FP8` needs sm_89+ (RTX 4090), `SAGE_FP8_SM90` Hopper.

### AMD (RX 7900 XTX, same layer shape)

| Backend | 16k tokens | 64k tokens | Note |
|---|---|---|---|
| **`TORCH_FLASH` (AOTriton)** | **13.9 ms** | **210–223 ms** | needs `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` |
| `TORCH_EFFICIENT` | 13.5 ms | 219 ms | same AOTriton kernels |
| `TORCH_MATH` | OOM (7 GB alloc) | — | |
| SageAttention 1.0.6 (Triton INT8) | 42.2 ms | 677 ms | **3× slower**; Sage 2 CUDA kernels don't exist for ROCm |
| flash-attn 2.8.4 Triton-AMD | — | — | pulls AITER; JIT fails (`-lamdhip64` in TheRock venv layout), breaks the image's triton |
| **SLA 75 % sparse** (Raylight `RayMiniMaxH3SLA`, Triton) | 5.5 ms | 83 ms | 2.7× |
| SLA 90 % sparse | 2.8 ms | 32.6 ms | 6.9× |

`AITER` targets Instinct (CDNA3), not RDNA3. For reference, the 7900 XTX's AOTriton Flash (13.9 ms) is faster than a 3090's
plain Flash (18.7 ms) and close to a 3090 with Sage (11.6 ms).

## 7. Model variants and quality

### 7.1 The pruned model

| | Full `minimax_h3_fl2va_bf16` | **Pruned `minimax_h3_fl2va_pruned_bf16`** (used for all runs) |
|---|---|---|
| Parameters | 33.1 B | **20.1 B** |
| File (bf16) | 66.3 GB | **40.2 GB** |
| Transformer blocks | 50 | 50 |
| Hidden / heads / head dim / MLP | 5376 / 56 / 128 / 14336 | identical |
| Attention + MLP weights | — | identical shapes |
| Per-block `adaln_proj.linear.weight` | **96768 × 2688** (260 M params) | **96768 × 8** |
| Time embedder (`time_embedder.proj_in/out`) | present | **removed**, replaced by a precomputed `adaln_t_table` |

Read from the safetensors headers: the remote one for the full model (no download), the local one for the pruned model. Pruning removed **~13 B parameters (≈40 %), all from the
timestep-conditioning (adaLN) path**. The step is a single scalar, so the adaLN outputs trace a 1-D curve over the steps, which
a small basis (8 coefficients over a precomputed table) represents closely. ComfyUI describes it as *"adaln shipped over a
precomputed curve basis (no time embedder)"*. Nothing that encodes image/motion/audio content was removed.
- Speed: essentially unchanged (those matrices are negligible next to attention over ~100k tokens).
- Memory: −26 GB in bf16. This is what makes 4-GPU FSDP (~10 GB/GPU) and 8-GPU FSDP (~5 GB/GPU) practical.
- Quality: expected near-identical; **the full model was not A/B tested** (66 GB download, disk was ~96 % full).

Speed: Q4 doesn't make the maths faster on these GPUs (dequantized to bf16 on the fly). It helps by (a) removing FSDP all-gather
traffic (large effect on short clips and on the ACS-limited AMD bus: 1.7×; smaller at 15 s: ~11 %) and (b) the Q4 text encoder fitting on
one card (2.5 min → ~40 s).

Same-seed quality, frames at 6 s and 12 s:
- **Q4 vs bf16** (NVIDIA N3 vs N2): same scene, timeline and end-card text; details and camera differ like a nearby seed
  (SSIM 0.44 over the clip). The 4-step LoRA amplifies small numeric differences. No visible artefacts or loss of detail from Q4.
- **Q4 on NVIDIA vs Q4 on AMD** (N3 vs F1): nearly the same frames (SSIM 0.61, the highest cross-run match), so the GGUF path is
  numerically consistent across vendors.
- Determinism: the same N3 job at capped vs default clocks produced a **bit-identical** video (SSIM 1.000), so clock and power
  settings change speed only.

### 12.1 NVIDIA PLX board bandwidth and why peer traffic leaves the switch

Measured after the reseat on the 4 NVIDIA PLX cards (`p2p-concurrent.py` with `CUDA_VISIBLE_DEVICES=2,3,4,5`):

| Card | Link under load | H2D / D2H | P2P to the other PLX cards |
|---|---|---|---|
| 30:00.0 | Gen4 x16 | 25.2 / 26.3 GB/s | 25.5 GB/s |
| 33:00.0 (MSI SUPRIM X) | **Gen4 x8** | 13.4 / 13.2 GB/s | 13.2 GB/s |
| 34:00.0 | Gen4 x16 | 25.4 / 26.3 GB/s | 25.5 GB/s |
| 37:00.0 | Gen4 x16 | 25.4 / 26.3 GB/s | 25.5 GB/s |

Concurrent copies (two pairs, bidirectional, 4-way ring) never exceed **25.6 GB/s in total**, one x16 link's worth: peer traffic
goes up to the root port and back instead of being switched locally. Cause: the kernel runs `amd_iommu=on` with the default
domain **Translated**. The NVIDIA PLX group (24) is `DMA-FQ`, so GPU-to-GPU writes target IOVAs that only the root complex can translate.
The AMD PLX group (13) is already `identity`, but it still caps at ~27.6 GB/s, so ACS redirect is the likely cause there. Root is needed
to read `ACSCtl`; the IOMMU groups merge all GPUs per board, so Linux doesn't see the ports as isolated.
Fix (root + reboot): kernel arg `iommu=pt`, and clear ACS redirect on the PEX downstream ports (BIOS or `setpci`).

### 12.4 Why collectives stop at ~6–7 GB/s on both vendors, and what would lift it

Same benchmark on the **4 NVIDIA PLX 3090s** (`scripts/p2p-full.py`, `scripts/rccl-bench.py`):
- One pair: 24.9–25.5 GB/s in each direction; bidirectional total 25.3–25.6.
- Every concurrent pattern (pairs, ring, all-to-all, one-to-all) totals **25.5–25.6 GB/s**.
- Latency 29–38 µs per 4 KiB copy (AMD 84–100 µs).
- NCCL collectives: **6.3–6.4 GB/s** bus bandwidth at all sizes.

| Setting (256 MiB, 4 GPUs) | AMD RCCL bus bw | NVIDIA NCCL bus bw |
|---|---|---|
| baseline (P2P, AMD 2 / NVIDIA 4 channels) | 6.9–7.0 | 6.3–6.4 |
| P2P_LEVEL=PXB (AMD) | 6.9–7.0 | — |
| 4 / 8 channels forced | 7.0 | 6.4 (8 ch) |
| P2P-op channels 8 | 6.9–7.0 | 6.4 |
| BUFFSIZE 16 MiB | 6.9–7.0 | 6.4 |
| PROTO Simple / LL128 | 6.9–7.0 | 6.3–6.4 / 6.0 |
| ALGO Tree | 6.9–7.0 | failed (not valid for this setup) |
| copy engine (`P2P_USE_CUDA_MEMCPY`) | 5.9–6.7 | 5.2–6.2 |
| fine-grain PCIe off (AMD) | 6.9–7.0 | — |

**Conclusion:** bus bandwidth ≈ the board's aggregate peer ceiling ÷ number of GPUs (NVIDIA 25.5/4 = 6.4, AMD 27.8/4 = 7.0).

already run at that physical limit; no library setting helps. The fix is making the switch route peer traffic locally:
1. **Clear ACS redirect** on the PEX ports: `sudo scripts/pcie-p2p.sh status`, then `clear` (runtime, reverts on reboot) or the BIOS option.
2. **NVIDIA board also needs `iommu=pt`**: its GPU group is in a translated (`DMA-FQ`) IOMMU domain. The AMD group is already `identity`.
If peer traffic stays in the switch, each ring hop gets its own x16 link and collectives could approach ~20–25 GB/s (≈3–4×, *estimate*).

1. **fp8_e5m2 KV cache → garbage output** on gfx1100 ("To inf"); found by bisecting. Use `--kv-cache-dtype auto`.
2. **Decode collapsed with context** on vLLM's default `ROCM_ATTN` (113.7 tok/s @1K → 4.5 @256K). Causes: ROCM_ATTN's decode kernels don't
   split the KV cache; TRITON_ATTN's split-KV ("3D") kernel is only used for 1-token steps, but MTP verifies 4; and the MTP draft
   layer silently gets ROCM_ATTN.
3. **Fix:** `--attention-backend TRITON_ATTN`, `"attention_backend":"TRITON_ATTN"` inside `--speculative-config`, and
   `patches/patch_triton_3d_specdecode.py` (3D kernel for steps ≤ 8 tokens; it already indexes partial results per token).

Needle recall at ~170K tokens (10 / 50 / 90 % depth): 3/3 on both ROCm 10 and 7.14. On gfx1100 vLLM offers only ROCM_ATTN and
TRITON_ATTN for the decoder (AITER backends need CDNA3+; TURBOQUANT rejected for this model; FLASH_ATTN/FlashInfer are CUDA-only).
ROCm 7.14 vs 10 is within 3–5 %; the attention path was the 11× lever. Remaining gap: TRITON_ATTN prefill is ~3× slower than
ROCM_ATTN from 64K up, and decode above 64K is still below the 3090s.

**TurboQuant (KV-cache compression, not a separate model):** data-free (Hadamard rotation + Lloyd-Max), enabled with
`--kv-cache-dtype turboquant_{4bit_nc,k3v4_nc,3bit_nc,k8v4}` on the same GPTQ checkpoint; vLLM then picks the `TURBOQUANT` backend.
`turboquant_4bit_nc`, TP=4: KV pool **3.73M tokens** (vs 857K fp16), needle 3/3 at ~170K, prefill 2.5× faster than TRITON_ATTN at 256K
(its prefill uses flash-attn), decode = TRITON_ATTN without MTP (24.3 tok/s @256K). Needs `FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE`
on the ROCm 10 image (its flash-attn is a CK build for MI-series → "device kernel image is invalid" on gfx1100). **With MTP (k=3)
vLLM refuses:** "Unsupported attention metadata type for speculative decoding with num_speculative_tokens > 1: TurboQuantMetadata".
Use it when capacity / many concurrent long requests matter more than single-stream decode; keep the TRITON_ATTN+MTP config for speed.
